# mybot

Меню управления телеграм-ботами на сервере. Одна команда вместо
запоминания путей, виртуальных окружений и имён screen-сессий.

```
  МОИ БОТЫ     04.11.2026  15:30
  ════════════════════════════════════════════════
   1) ARTEMIS       ● работает  (pid 4231 · 02:14:50 · 180 МБ)
   2) AZUREIPAUTO   ● работает  (pid 4588 · 00:31:02 · 95 МБ)
   3) DILLERBOT     ○ остановлен
   4) Выход
```

Внутри любого бота: запустить, перезапустить, остановить, смотреть
лог, войти в сессию screen.

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/arhman92/mybot/main/install.sh | bash
```

Или скачать репозиторий архивом, распаковать и выполнить внутри:

```bash
bash install.sh
```

Нужен `root`. Скрипт кладёт команду в `/usr/local/bin/mybot` и
ставит `screen`, если его нет. Больше ничего не трогает.

## Как пользоваться

```bash
mybot          # меню
mybot status   # состояние всех ботов одной строкой
```

## Что полезно знать

**Логи пишутся сами** — в `/root/4idea/Artemis/logs/`. Отдельный файл
на каждого бота. Раньше вывод пропадал вместе с закрытым screen.

**Второй раз один бот не запустится.** Два процесса с одним токеном
отбирают события друг у друга: бот начинает «терять» нажатия, а
причину потом ищешь полдня.

**Остановка сначала просит по-хорошему** и ждёт десять секунд. Не
послушался — останавливает жёстко.

**Если бот не поднялся**, меню сразу показывает последние строки
лога. Не надо никуда лезть и искать.

**После перезагрузки сервера** команда на месте, а боты не
поднимаются. Это нарочно: поднимешь их сам, когда убедишься, что
панель и база на месте.

## Настройка под свои пути

Всё в начале файла `/usr/local/bin/mybot`:

```bash
PY="/root/4idea/Artemis/venv/bin/python"   # питон ботов
LOGS="/root/4idea/Artemis/logs"            # куда писать логи

BOTS=(
  "ARTEMIS|/root/4idea/Artemis|main.py|artemis"
  "AZUREIPAUTO|/root/4idea/Artemis/azureipauto|bot.py|azureipauto"
  "DILLERBOT|/root/4idea/Artemis/dillerbot|bot.py|dillerbot"
)
```

Формат строки: `ИМЯ | папка | файл | имя screen-сессии`.
Добавить бота — дописать строку, больше ничего менять не надо.

## Зависимости ботов

В `requirements.txt` лежит список библиотек с теми версиями, на
которых всё работает. Важная строка там одна:

```
azure-mgmt-resource==23.0.1
```

В версии 26 из `azure.mgmt.resource` убрали `ResourceManagementClient`,
и бот падает на первом же импорте с невнятным
`cannot import name ... (unknown location)`. Версия прибита нарочно.

Поставить всё разом:

```bash
cd /root/4idea/Artemis
python3.11 -m venv venv
venv/bin/pip install -U pip
venv/bin/pip install -r requirements.txt
```

Нужен Python 3.10 или новее — в коде есть `match`. На CentOS 9 по
умолчанию стоит 3.9, поэтому `dnf install -y python3.11`.
